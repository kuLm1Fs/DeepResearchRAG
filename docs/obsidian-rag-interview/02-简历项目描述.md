# 简历项目描述

## 项目背景版

RAG Finance Intelligence｜金融领域双语 RAG 智能问答系统

面向金融研究、企业知识库和合规审计场景，构建从多源采集、向量入库、混合检索、LangGraph Agent 问答到企业级多租户部署的端到端 RAG 系统。数据层接入财经 RSS（CNBC / Bloomberg / FT / WSJ / 华尔街见闻 / 财新 / 第一财经等）、SEC 财报（FinanceBench 150 条）、飞书企业知识库、Hacker News 和 HuggingFace 金融数据集，能够在 4 核 / 15.6GB 服务器上稳定处理 10 万到 100 万篇金融文档，输出带来源引用和审计追踪的 SSE 流式回答与研究报告。

## 后端 / AI 应用方向

- 设计并实现金融数据 ingestion pipeline，接入财经 RSS、飞书 Open API（Wiki + Docx）、SEC 财报、Hacker News 和 HuggingFace 金融数据集，完成清洗、chunk 切分、content_hash 去重、Embedding 批处理和 Milvus 增量入库。
- 搭建企业级 RAG 后端：JWT 认证（refresh token SHA256 哈希存储）、多租户 company_id 隔离、租户配额、审计日志、错误分级和 trace_id 全链路追踪。
- 构建多路召回检索链路，融合语义向量检索、关键词检索和标题匹配，通过 RRF（k=60）、时间衰减、来源质量加权和可选 CrossEncoder reranker 提升金融场景下 Precision@5。
- 基于 LangGraph 编排 RAG Agent 和 5 阶段 Deep Research（Planner→Retriever→Analyst→Checker→Writer），通过 max_tool_calls 和可行动缺口判断控制执行边界。
- 搭建评测体系：FinanceBench 150 条 SEC 评测集 + LLM 自动生成金融 QA + LLM-as-Judge（faithfulness / relevance / citation coverage / correctness），按难度分层统计。
- 封装 DeepSeek / OpenAI / Qwen 多 LLM Provider 抽象和 Prompt 版本管理，加入 LLM cache、debug 日志和生产环境保护策略。
- 飞书集成：完整 Open API 客户端（token 缓存、限速、重试）、Block → Markdown 解析、Collector 自动注册，配 36 个专项测试。
- 通过 GitHub Actions 跑前后端 CI：ESLint + Vite build + 133 个 pytest 测试全绿。

## 全栈方向

- 独立搭建金融领域双语 RAG 系统，后端采用 FastAPI、LangGraph、Milvus 和火山引擎 Embedding，前端采用 React、TypeScript、Vite、Tailwind 和 DaisyUI。
- 实现 SSE 流式问答接口和前端聊天界面，支持实时输出、来源面板、来源卡片、研究任务进度、质量报告和 Markdown / PPT 报告展示。
- 设计认证流：登录 / 注册 / 自动刷新 / 登出，前端 API client 统一管理 access_token，所有 fetch 自动带 Authorization 头。
- 补齐多租户前端表达：注册时绑定 company_name，导入任务可选 RSS / HN / HF / 飞书，类型与后端严格对齐。
- 设计多源金融数据采集和增量入库流程，支持财经 RSS、飞书知识库、SEC 财报、HN 和 HF 金融数据集，使用 content_hash 降低重复写入。
- 实现 semantic / keyword / title 三路召回和 RRF 融合排序，结合时间与来源加权，提高金融实体查询和复杂语义查询的召回稳定性。
- 整合企业级能力：JWT 认证、多租户字段、审计日志、trace_id、结构化日志和错误分级，使系统具备从 demo 到可部署应用的基础条件。

## AI Agent 方向

- 使用 LangGraph 设计多阶段 RAG Agent，将 Query Analysis、Route Decision、Retrieval、Evaluation、Source Comparison、Answer Generation 和 Self-reflection 拆成可观测节点。
- 扩展 5 阶段 Deep Research：Planner（目标拆解）→ Retriever（多跳证据检索）→ Analyst（趋势归纳）→ Checker（缺口 / 冲突 / 时效）→ Writer（Markdown 报告 + PPT 大纲）。
- 设计 evidence_trace、execution_log、quality_report 和 memory_snapshot，记录证据来源、执行状态、质量指标和研究上下文，使 Agent 结论可追溯、可恢复、可复盘。
- 通过 max_tool_calls、可行动缺口判断和配置类缺口过滤控制 Agent 执行边界，降低开放式研究任务中的循环补检风险。
- 接入 LLM-as-Judge 作为端到端评测信号，从 faithfulness / relevance / citation coverage / correctness 四个维度打分，按 easy / medium / hard 难度分层。

## 自我介绍 30 秒版

我最近做了一个金融领域双语 RAG 系统，核心是把财经 RSS、飞书企业知识库、SEC 财报、Hacker News 和 HuggingFace 金融数据集里的内容统一处理成可检索、可隔离的证据库。后端用 FastAPI 和 LangGraph，向量库用 Milvus，Embedding 走火山引擎 API。检索上我做了语义、关键词和标题三路召回，用 RRF 做融合，再结合时间衰减、来源权重和可选 reranker 排序。Agent 层除了基础问答，还有 5 阶段 Deep Research，能产出可追溯的研究报告。系统还搭了企业级能力：JWT 认证、多租户隔离、配额、审计日志、CI 全绿。
