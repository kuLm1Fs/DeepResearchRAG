# 技术架构速查

## 技术栈

| 层级 | 技术 |
| --- | --- |
| 后端 | Python 3.10+, FastAPI, Pydantic |
| Agent / RAG | LangChain, LangGraph |
| LLM | DeepSeek, OpenAI, Qwen (env `LLM_PROVIDER` 切换) |
| Embedding | 火山引擎 Embedding API, dim=1024, batch_size=50, tenacity 3 次重试 |
| 向量库 | Milvus standalone, IVF_FLAT, COSINE, nlist=128 |
| 结构化存储 | PostgreSQL 16 (用户、租户、配额、审计、任务) |
| 对象存储 | MinIO |
| 数据源 | 财经 RSS / Hacker News / HuggingFace / FinanceBench / 飞书 Open API |
| 认证 | JWT (access_token 15 min, refresh_token 7 d), refresh token SHA256 哈希存储 |
| 前端 | React 18, TypeScript, Vite, Tailwind, DaisyUI |
| 测试 | pytest (133 个), ESLint, GitHub Actions |
| 部署 | Docker, Docker Compose |
| 日志 | structlog, trace_id, 敏感信息脱敏 |

## 数据链路

```text
财经 RSS / HN / HF Dataset / FinanceBench / 飞书 Wiki+Docx
  -> Collector (标准化字段)
  -> 清洗 (去 HTML / 去 boilerplate / Block → Markdown)
  -> chunk (RecursiveCharacterTextSplitter, chunk_size=500)
  -> content_hash (SHA256) 去重
  -> 火山引擎 Embedding (batch_size=50)
  -> Milvus insert (带 company_id 隔离标记)
```

## 检索链路

```text
Query (with company_id)
  -> Query Analysis (LLM 路由)
  -> semantic search (embedding + COSINE)
  -> keyword search (Milvus FULLTEXT on title + content)
  -> title search (精确命中)
  -> RRF fusion (k=60, weights 0.5/0.3/0.2)
  -> time decay boost
  -> source quality boost
  -> optional CrossEncoder reranker (BAAI/bge-reranker-v2-m3)
  -> top evidence (按 company_id 隔离)
```

关键文件：

- `backend/src/retrieval/retriever.py`
- `backend/src/retrieval/fusion.py`
- `backend/src/retrieval/boost.py`
- `backend/src/retrieval/reranker.py`

## Agent 链路

基础问答：

```text
Analyze Query
  -> Route Decision
  -> Multi-path Retrieval
  -> Result Evaluation
  -> Source Comparison
  -> Answer Generation (带引用)
  -> Self Reflection
```

Deep Research：

```text
Planner
  -> Retriever
  -> Analyst
  -> Checker (evidence coverage, diversity, freshness, gaps, conflicts)
  -> Writer (Markdown + PPT outline)
  ^   |
  |___|  (可行动缺口时回到 Retriever, max_tool_calls=20)
```

## 飞书集成

```text
Wiki Spaces (list)
  -> Space IDs (auto-discover or config)
  -> list_nodes (DFS, recursive)
  -> filter obj_type == "docx"
  -> get_document_blocks (paginated, rate limited 5 req/s)
  -> blocks_to_text (Markdown 转换, 30+ block types, table 重建)
```

## 评测链路

```text
评测集 (FinanceBench 150 + LLM 自动生成)
  -> evaluate_retrieval.py
      -> 跑多路检索
      -> 算 Precision@K / Recall@K / NDCG@K
  -> evaluate_e2e.py
      -> 调 RAG Agent 拿答案
      -> LLM-as-Judge 打 faithfulness / relevance / citation coverage / correctness
  -> 按 easy / medium / hard 分层统计
  -> 写 data/eval_results/{date}.json
```

## 面试时最值得提的参数

- chunk_size: 500
- Embedding dim: 1024
- Embedding batch_size: 50
- Embedding retry: 3 attempts, exponential backoff
- Milvus index: IVF_FLAT
- metric: COSINE
- nlist: 128
- RRF k: 60
- RRF weights: semantic 0.5, keyword 0.3, title 0.2
- access_token TTL: 15 min
- refresh_token TTL: 7 d (SHA256 哈希存储)
- max_tool_calls (Deep Research): 20
- pytest: 133 个测试全绿
- 飞书限速: Wiki 100 req/min, Docx 5 req/s
- 目标规模: 10 万到 100 万篇金融文档
- 目标资源: 4 核 / 15.6GB
- 检索目标: Precision@5 >= 0.8
- 评测集: FinanceBench 150 + LLM 自动生成
