# 面试表达模板

## 15 秒版

我做过一个金融领域双语 RAG 系统，后端用 FastAPI、LangGraph 和 Milvus，检索上做了语义、关键词、标题三路召回和 RRF 融合；数据层支持财经 RSS、飞书企业知识库、SEC 财报和 HF 金融数据集；Agent 层除了基础问答还有 5 阶段 Deep Research；配套 JWT 认证、多租户隔离、配额、审计日志和 GitHub Actions CI。

## 30 秒版

这是一个金融场景的双语 RAG 系统。数据层支持财经 RSS、飞书知识库、SEC 财报、Hacker News 和 HuggingFace 金融数据集，采集后做 chunk、Embedding、content_hash 去重写入 Milvus。检索层做 semantic / keyword / title 三路召回，用 RRF、时间衰减、来源质量加权和可选 reranker 排序。Agent 层用 LangGraph 编排查询分析、检索、评估、多源对比、答案生成和自反思；Deep Research 拆成 Planner / Retriever / Analyst / Checker / Writer 五阶段。前端通过 SSE 展示流式回答和来源卡片。企业级能力包括 JWT 认证、多租户隔离、配额、审计日志、trace_id 和 CI。

## 1 分钟版

RAG Finance Intelligence 是我做的一个金融领域双语 RAG 系统，目标是把分散的金融信息源沉淀成可检索、可隔离、可追溯的证据库。

数据层支持财经 RSS（CNBC / Bloomberg / FT / WSJ / 华尔街见闻 / 财新 / 第一财经）、飞书企业知识库、SEC 财报（FinanceBench 150 条）、Hacker News 和 HuggingFace 金融数据集，入库前做清洗、chunk、content_hash 去重和火山引擎 Embedding，最后写入 Milvus。

检索层我做了三路召回——语义向量、关键词、标题匹配，用 RRF 融合，结合时间衰减、来源质量加权和可选 CrossEncoder reranker 提升前几条证据质量。Agent 层用 LangGraph 拆成查询分析、路由、检索、评估、多源比较、生成和自反思；Deep Research 进一步拆成 5 阶段。工程上加了 JWT 认证、多租户隔离、配额、审计、trace_id、结构化日志、敏感信息脱敏、检索评估脚本和 GitHub Actions CI。

## 3 分钟版

我从业务问题、技术架构和项目难点三个角度讲。

业务上，金融场景有四个痛点：信息分散且专业（财经 RSS + 飞书 + SEC 都要接）、合规与可追溯要求高（金融答案代价大，每条 claim 必须有 supported citation）、多用户隔离（一个平台服务多家公司）、研究任务长且发散（多跳、多源、长链路）。

架构上，项目分七层——企业接入层（JWT / 多租户 / 配额 / 审计）、数据采集层（财经 RSS / 飞书 / SEC / HN / HF）、数据处理层（清洗 / chunk / 去重）、向量存储层（火山引擎 Embedding + Milvus）、检索层（三路召回 + RRF + boost + reranker）、Agent 层（LangGraph + 5 阶段 Deep Research）、交付层（FastAPI SSE + React + Vite + Tailwind）。

难点上，我重点解决了五个问题。

第一，金融多源质量不稳定，所以采集链路做了标准化 + 容错 + 去重 + 溯源字段（飞书专门做了 Client + Block Parser + 36 个测试）。

第二，金融检索查询类型混合，所以三路召回 + RRF 融合 + 时间 / 来源 boost + reranker 优化前排质量。

第三，金融 Agent 开放任务容易失控，所以 LangGraph 拆 5 阶段 + max_tool_calls + 可行动缺口判断。

第四，金融结论必须可追溯，所以保存 evidence_trace / execution_log / quality_report / memory_snapshot，Citation Coverage 是硬指标。

第五，企业级多租户隔离，所以 company_id 强制从索引层过滤 + 配额 + 审计 + JWT refresh token 哈希存储。

## 被问"你最大的贡献是什么"

最大贡献是把这个项目的核心链路串起来：从金融多源采集、清洗切分、Embedding 入库，到 Milvus 三路检索 + RRF 融合 + 时间 / 来源 boost，到 LangGraph Agent + 5 阶段 Deep Research，到 SSE 前端 + 来源卡片 + 研究任务面板。里面我重点做了：

- 金融场景下的混合检索策略（三路 + RRF + boost + reranker）
- Agent 节点编排（基础 7 节点 + Deep Research 5 阶段）
- 证据追踪 + LLM-as-Judge 评测体系
- 企业级能力（JWT + refresh token 哈希 + 多租户索引层隔离 + 配额 + 审计）
- 飞书完整产品化集成（Client + Collector + Block Parser + 36 个测试）
- GitHub Actions CI（133 个测试全绿）

## 被问"项目有什么不足"

四个可以继续优化的点。

第一，全文检索可以更强。Milvus FULLTEXT 能用，后续可以引入 Elasticsearch 或 OpenSearch，提升复杂关键词、短语、高亮能力。

第二，评测集还可以扩大。FinanceBench 150 条 + LLM 自动生成是基础，后续应该补更多真实金融查询、中文深度查询、多跳问题、跨期对比问题。

第三，reranker 成本控制。CrossEncoder 精排效果好但延迟和资源成本高，线上可以只对 topN 候选开启，或者按 query 类型动态启用。

第四，长期研究记忆可以产品化。现在有 memory_snapshot 和 gaps，后续可以做任务版本、对比报告、定期自动更新。
